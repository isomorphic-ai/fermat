# Credit-ladder findings

Newest findings are recorded first.

## 2026-07-30 — CREDIT-FLOW starts at one genuinely high coefficient

- The pinned `KummerCriterion` dependency contains a genuine generic
  generator-to-log construction: its completed same-prime logarithm is
  additive on products and sends `p`-th powers to `p`-multiples.  Its
  concrete Kummer matrix is proved to be a Bernoulli row diagonal times a
  Vandermonde matrix.  This is a fair external boundary and confirms the
  proposed stock/flow architecture.
- That packaged matrix is nevertheless only the low, mod-`p` reading.  Its
  fixed Dwork coordinates have exponents below `p`, and its eigenvalue in
  row `j` is the reduction of `B_(2j)/(2j)`.  At an irregular prime this
  loses exactly the row needed here.  Repository-wide inspection found no
  external theorem extracting the high `2*j*p - 1` logarithmic derivative
  or identifying it, at `p^3` precision, with `B_(2*j*p)`.
- W1 and W2 must therefore keep two levels distinct.  The high flow produces
  integral character congruences
  `p^3 ∣ transformedCoefficient * highBernoulliNumerator`; cube-freeness
  gives divisibility of each transformed coefficient by `p`; only then may
  the row-scaled Vandermonde be reduced modulo `p` and inverted.  A flow
  valued only in `Fin rank → ZMod p` is too weak.
- The current Markdown certificate gives all high Bernoulli residues modulo
  `p^3`, but there is no clean-cone Lean theorem checking them.  The existing
  proofs transitively import forbidden irregular/Vandiver modules.  The thin
  instance therefore needs a new kernel-checked residue vector with a
  specification theorem; the exceptional human row 22 is Lean index 21.

## 2026-07-30 — the old declaration guard is not an import guard

- `Verification.lean` says that it rejects a forbidden “namespace or module
  prefix”, but its command inspects only `env.constants`.  In particular,
  importing `Fermat.FiftyNine.FirstCase` would not necessarily create a
  declaration below the module's full name because that file declares in
  `Fermat.FiftyNine`.
- CREDIT-FLOW verification must inspect `env.header.moduleNames` as well as
  declarations, explicitly reject the five superseded seam-chain modules,
  and run the selected-prime source-literal gate.  The generic credit
  sources currently contain no selected-prime literal, so the new gate has
  a clean baseline.

## 2026-07-29 — C3 has a clean generated algebraic core and one arithmetic input

- Vandiver's final unit-power argument is independent of cyclotomic
  enumeration.  For the edge family generated by one cycle, finite index
  supplies a power/product relation; primitive normalization, the
  coefficient congruences, and Bézout then construct a `p`-th root.
- This algebraic core can be reconstructed under the credit namespace from
  Mathlib alone and credited explicitly to Vandiver's Lemma II.  It will be
  specialized to the cycle's edge family, rather than accepting an arbitrary
  hidden unit provider.
- The irreducible C3 arithmetic input is narrower than "repayment": a deep
  local congruence must imply the coefficient-cube congruences for every
  primitive generated relation.  The rung must name this input exactly.
  Supplying a power root, a repayment function, or an endpoint proposition
  would conceal the obligation and is not acceptable.

## 2026-07-29 — capacity is an index only after its ambient boundary is explicit

- `Subgroup.relIndex` is the useful route-neutral representation of
  capacity, but it is defined using intersection and returns zero at infinite
  index.  A capacity object therefore needs the generated sub-ledger, the
  ambient ledger, a proof that the former lies in the latter, and finite
  relative index before it may be described as finite capacity.
- A numerical determinant can check an index fact only after a realization
  map connects its columns to the generated edge family.  This adapter and
  the determinant/index theorem are part of C2's certificate boundary; the
  matrix itself cannot define either the family or its capacity.

## 2026-07-29 — one cycle generates the matrix, the unit family, and both sides

- The useful route-neutral generator is a cycle with `rank + 1` nodes.  Its
  `rank` successive edge ratios generate the sub-ledger.  This matches a
  unit rank of 28 with a Galois cycle of order 29 without supplying 28
  independent seeds.
- The credit matrix is a node-pair matrix whose entries are sets of
  generators.  Pointwise union is its semilattice merge.  Transposition is
  the receivable view of the same matrix, so two-sidedness requires no second
  collection of data.
- C1 is consequently absence of a funded generator: when the generator type
  is empty, the generated matrix is bottom.  It is not a separately asserted
  table of zero entries.
